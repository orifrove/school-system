# Telegram bot: запуск и проверка

## Запуск на Windows

Из папки backend с активированным venv:

```powershell
python manage.py check
python manage.py migrate
python manage.py run_bot
```

После изменения кода остановите предыдущий процесс бота через Ctrl+C
и запустите run_bot снова. Для одного токена должен работать один polling-процесс.

## Приглашение

Администратор создаёт User, назначает бизнес-роль через UserRole и выдаёт
активный InviteCode с будущим expires_at. Использованный код не нужно
переводить обратно в active: used_at защищает от повторного использования.
Для изменения уже существующей Telegram-привязки нужен отдельный
административный процесс; приглашения её не перезаписывают.

В личном чате отправьте /start, затем код. После успешной активации
повторный /start должен приветствовать пользователя по имени.
Отключённые аккаунты не могут пользоваться меню или активировать приглашения.

/start и /menu показывают кнопки по ролям. Teacher видит «Мои группы»
и «Моё расписание», Parent — «Мои дети». При двух ролях доступны все разделы.
Роль назначает администратор через UserRole; родство задаётся отдельно
через ParentStudent и не возникает автоматически из роли.

## Группы и посещаемость

1. У User должна быть роль Teacher, а Group.teacher должен ссылаться на него.
2. Группа и ученики должны быть активными. Нужны Schedule и Lesson;
   Lesson.teacher должен соответствовать преподавателю.
3. У ученика должен быть active Enrollment в группе, действующий
   на локальную дату занятия (Asia/Tashkent).
4. Отправьте /groups, выберите группу, занятие и ученика.
5. Выберите «Присутствует», «Отсутствует», «Опоздал» или
   «Уважительная причина». Вернитесь в список и проверьте отметку.

Повторная отметка обновляет запись Attendance. Отменённые занятия скрыты
и недоступны для записи. Старые кнопки после смены учителя не дают доступа
к бывшей группе. Списки показываются страницами по восемь записей.

Вверху списка показан прогресс: сколько учеников отмечено и сколько имеют
хотя бы одну оценку за занятие. Счётчики охватывают все страницы списка.
Кнопка «Следующий неотмеченный» открывает первого ученика без отметки
в алфавитном порядке; она доступна и после сохранения посещаемости.
При нажатии список проверяется заново, поэтому старая кнопка не выбирает
уже отмеченного ученика, если остались другие.

«Итоги занятия» показывает количество учеников по четырём статусам,
число неотмеченных и учеников с оценками. Несколько оценок одного ученика
считаются как один ученик с оценками. Когда все отмечены, появляется
сообщение о заполненной посещаемости. Статус самого Lesson не меняется:
заполненный журнал не означает автоматического проведения занятия.

## Расписание учителя и индивидуальные занятия

Откройте /schedule или /menu → «Моё расписание». Кнопки «Сегодня», «Завтра»
и «7 дней» выбирают календарный период по Asia/Tashkent. Сегодня включает
и уже начавшиеся занятия текущего дня; «7 дней» — сегодня и следующие
шесть дней. Отменённые занятия скрыты. Записи отсортированы по времени.

В списке есть группы и индивидуальные занятия с именем ученика. Нажмите
занятие, чтобы открыть журнал: посещаемость, оценки и итоги работают
для обоих форматов. Индивидуальное занятие использует именно Enrollment
из Schedule, даже если у ученика есть другие индивидуальные программы.
Для доступа нужны текущая связь с обучением и совпадение Lesson.teacher.

В индивидуальном журнале кнопка возврата открывает расписание; в групповом
— занятия группы. Учебные записи не меняются от открытия расписания.

## Оценки

Из /groups откройте занятие и карточку ученика, нажмите «Поставить оценку».
Выберите 2, 3, 4 или 5. Кнопка «Своя оценка» позволяет отправить значение
сообщением, например 8/10, 95 или A. Ограничение — 16 символов, одна строка.
Быстрые кнопки не задают обязательную шкалу оценивания центра.

После сохранения вернитесь в карточку: там показаны последние пять оценок
за выбранное занятие. Повторное нажатие использованной кнопки не создаёт
дубль. Чтобы поставить ещё одну отдельную оценку, откройте выбор заново.
Это добавление оценки, а не исправление предыдущей: существующая запись
и её автор сохраняются.

Отменить свой ввод можно кнопкой «Отмена», /cancel, /groups или /start.
При неверном формате можно отправить исправленное значение. При изменении
доступа или оценок нужно снова открыть карточку. Состояние незавершённого
ввода хранится в памяти: после перезапуска бота откройте меню заново.

Проверка: поставить оценку 5; повторить нажатие старой кнопки и убедиться,
что дубль не появился; открыть меню заново и добавить 8/10 через свой ввод.
Оценки должны отображаться у правильного ученика и занятия.

## Родитель: дети, оценки и занятия

Для доступа нужны активный User с ролью Parent и связь ParentStudent
с активным Student. Привязка Telegram выполняется отдельным приглашением
для этого User. Если один человек одновременно преподаватель и родитель,
администратор назначает обе роли и создаёт связи с его детьми.

Откройте /menu → «Мои дети» (или /children), выберите ребёнка:

- «Оценки» — последние оценки, включая итоговые без привязки к занятию.
- «Посещаемость» — сохранённые отметки по занятиям.
- «Ближайшие занятия» — будущие planned-занятия, на которые действует
  активное зачисление ребёнка. Учитываются и группы, и индивидуальные занятия.

Время отображается по Asia/Tashkent. Данные разбиты на страницы по пять
записей; кнопки «Обновить», «К ребёнку» и «Все дети» позволяют переключаться
без повторного ввода команд. Пустой список показывает понятное сообщение.

После удаления ParentStudent старые кнопки больше не открывают сведения
о ребёнке. Проверьте отдельно аккаунт без связи: одна роль Parent не даёт
доступ к чужому ученику. Родительское меню только читает данные.

## Автоматическая проверка

Уведомления об оценках и посещаемости попадают в очередь при сохранении
через сервисы. Доставка пока запускается отдельной командой; предварительный
просмотр и обработка ошибок описаны в [NOTIFICATIONS.md](NOTIFICATIONS.md).

Для разработки можно подготовить отдельные синтетические данные:

```powershell
python manage.py seed_teacher_demo --teacher-id 123
```

Замените 123 на ID активного User с ролью Teacher из Admin. Команда
работает только при DEBUG=True: создаёт группу с префиксом [DEMO], двух
вымышленных учеников и занятие на сегодня в 18:00 по времени центра.
Повторный запуск за тот же день не создаёт дублей и не меняет посещаемость.
Если демо-группа вручную передана другому учителю, команда останавливается.
Перезапуск бота после добавления данных не требуется — снова откройте /groups.

Чтобы добавить также отдельного демо-ученика и индивидуальное занятие
на сегодня в 19:00, используйте:

```powershell
python manage.py seed_teacher_demo --teacher-id 123 --individual
```

Выполнив команду, откройте /schedule. Повторный запуск за тот же день
не создаёт повторных индивидуальных зачислений или занятий.

```powershell
python manage.py test --noinput
python manage.py makemigrations --check --dry-run
```

В родительском меню доступен раздел «💳 Оплаты»: `/children` → ребёнок →
«Оплаты» → «История платежей». Правила расчёта и проверки доступа описаны
в [PARENT_BILLING.md](PARENT_BILLING.md).

Тесты используют отдельную тестовую PostgreSQL-базу. Bot-тесты не отправляют
сообщений в Telegram. Живую проверку после перезапуска проводят отдельно.
