# Создание занятий из расписания

Сначала настройте Schedule в Django Admin: группу или индивидуальное
зачисление, день недели, время, кабинет и период действия.

Из корня проекта выполните предварительный просмотр:

```powershell
.\manage.ps1 generate_lessons --days 14
```

Начальная дата по умолчанию — сегодня по часовому поясу центра. Можно
указать её явно и выбрать одно расписание:

```powershell
.\manage.ps1 generate_lessons --start 2026-10-13 --days 14 --schedule-id 1
```

Замените ID и дату на нужные. После проверки добавьте `--apply` к той же
команде — только тогда новые занятия сохранятся. Диапазон: 1–90 дней,
включая начальную дату. В выводе не более 50 деталей, счётчики охватывают
весь диапазон. Preview не резервирует данные: перед записью они читаются снова.

## Правила

- Используются активные расписания в пределах valid_from/valid_until.
- Группа должна быть активна. Для индивидуального обучения также проверяются
  активность ученика, статус и даты зачисления.
- Преподаватель должен быть активен и иметь роль Teacher; предмет — активен.
- Даты границ включаются. Время берётся из шаблона в часовом поясе центра.
- Новое занятие получает текущие teacher, subject, room и статус planned.
- Существующие занятия не меняются, включая held и cancelled. Повторный
  запуск на тот же период не создаёт дублей одного schedule + starts_at.
- При некорректном шаблоне запись всей команды откатывается.

Изменение времени расписания создаёт другой starts_at: старые занятия
автоматически не переносятся и не удаляются. Праздники
учитываются ручной отменой конкретного занятия; повторный запуск отмену
сохранит. Начисления и уведомления команда не создаёт.

Новые модели и миграции не нужны. Автоматический запуск по таймеру не включён.

## Проверка пересечений

Preview показывает `CONFLICT` с ID расписания и существующего занятия
или другого расписания из новой партии. Проверяются преподаватель и кабинет:
интервалы должны пересекаться по времени. Занятия 18:00–19:00 и 19:00–20:00
совместимы. Отменённые занятия не занимают ресурсы; planned и held занимают.
Пустой кабинет не считается общим ресурсом. Названия кабинетов сравниваются
точно: используйте единое написание во всех расписаниях.

При любом конфликте `--apply` отказывается сохранять всю партию. Исправьте
расписание и повторите preview. `would_create` включает конфликтующие кандидаты;
`conflicts` считает кандидатов с найденным пересечением, а не все пары пересечений.
Показывается до 20 причин, по одной на конфликтующий кандидат.

Генератор и форма Lesson в Django Admin используют общую блокировку
PostgreSQL: второе сохранение проверяет уже записанные первым занятия.
Смена преподавателя группы через сервис и Admin использует ту же блокировку.
Прямые записи через ORM остаются вне этой защиты.
Проверяются только новые кандидаты: существующая история не исправляется
и не проходит полный аудит пересечений. Preview ничего не резервирует.

## Аудит уже созданных занятий

Проверка существующих занятий, в том числе созданных вручную через Admin:

```powershell
& "C:\Users\hp\Desktop\school system\manage.ps1" check_lesson_conflicts --days 14
```

Команда ничего не изменяет и не отправляет сообщения. Она выводит ID пары
занятий, причину (преподаватель, кабинет или обе) и интервал пересечения
по часовому поясу центра. Отменённые занятия исключаются; проведённые
учитываются. Каждая пара считается один раз. Пустые кабинеты не конфликтуют,
остальные названия сравниваются точно, как при генерации.

`--start YYYY-MM-DD` задаёт первую дату, `--days` — от 1 до 90 дней.
Учитываются также занятия, начавшиеся до указанного диапазона и продолжающиеся
внутри него. Конечная дата исключается. По умолчанию выводятся первые 20 пар;
`--limit 1..200` меняет предел, общий счётчик охватывает все найденные пары.
`--fail-on-conflict` возвращает ненулевой код завершения при пересечениях,
чтобы проверку можно было использовать в сценариях запуска.

Нулевое число проверенных занятий означает отсутствие сохранённых уроков
в диапазоне, а не подтверждает корректность шаблонов Schedule. Для шаблонов
используйте preview `generate_lessons`. Аудит не блокирует параллельное
редактирование расписания и не заменяет защиту при записи.

## Ручное создание и перенос в Admin

Форма Lesson проверяет пересечения при создании и при изменении времени,
преподавателя, кабинета или статуса. Ошибка выводится в форме с ID занятия,
датой и причиной; показывается до пяти конфликтов. Запись остаётся без изменений.
Равенство конца одного урока началу другого допустимо. Собственное занятие
из проверки исключается. Отмена освобождает ресурсы, восстановление отменённого
занятия заново проверяет занятость. Некорректный интервал отмечается у поля окончания.

Изменение прочих полей не блокируется из-за старых пересечений. Исторические
конфликты можно найти командой аудита. Проверка формы не является ограничением
базы данных: прямой ORM по-прежнему требует отдельного аудита. Проверка не меняет сохранённые teacher/subject на значения из Schedule.

## Смена преподавателя группы

Перед сохранением нового преподавателя в карточке Group проверяются все её
занятия со статусом planned (включая прошлые даты с таким статусом).
Если новый преподаватель занят, форма показывает ID конфликтующих уроков
и дату. Имя группы и остальные изменения также не сохраняются до исправления.
Пересечения между самими переносимыми занятиями тоже блокируют смену.

При успехе Group.teacher и учитель всех planned-занятий обновляются атомарно.
Проведённые и отменённые уроки сохраняют прежнего учителя. Отменённые занятия
нового учителя не блокируют смену; соседние по времени занятия разрешены.
Кабинеты при смене учителя не меняются, старые конфликты кабинетов проверяются
командой аудита. Для этой операции используется общая с генератором и формой
Lesson блокировка PostgreSQL. Необработанные записи через ORM обходят защиту.
