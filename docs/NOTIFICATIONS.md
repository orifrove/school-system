# Уведомления родителям

## Что реализовано

При создании оценки через education.services.add_grade и изменении
посещаемости через mark_attendance создаются записи Notification для
активных родителей, у которых есть роль Parent, ParentStudent и Telegram-привязка.
Учебная запись и очередь сохраняются одной транзакцией: при ошибке очереди
изменение учебной записи тоже откатывается.

Оценка имеет ключ события по ID. Посещаемость — по ID и времени изменения.
Повторное сохранение того же статуса посещаемости ничего не меняет:
не обновляет автора/время и не создаёт уведомление. Изменение статуса создаёт
новую версию. UNIQUE(recipient, event_key) защищает очередь от дублей.

Перед отправкой заново проверяются роль родителя, активность аккаунта и
ребёнка, Telegram-привязка и связь ParentStudent. Устаревшая версия
посещаемости пропускается: сообщение «Отсутствовал» не отправляется,
если до отправки отметку исправили. Уже отправленные сообщения не удаляются;
следующее изменение создаёт отдельное уведомление.

Прямое сохранение Grade/Attendance в Django Admin не вызывает эти сервисы
и не формирует очередь. Старые учебные записи автоматически не рассылаются.

## Просмотр перед отправкой

Из backend с активированным venv:

```powershell
python manage.py dispatch_notifications --limit 10
```

Это режим по умолчанию: сеть не используется, статусы не меняются.
Текст показан с Unicode-экранированием для совместимости с Windows-консолью.
Можно ограничить конкретным получателем через --recipient-id ID.
Перед реальной доставкой проверьте адресата и содержимое очереди.

## Явная отправка

```powershell
python manage.py dispatch_notifications --send --limit 10 --recipient-id 123
```

Замените 123 на ID нужного User. Команда отправляет настоящие сообщения
в Telegram, используя TELEGRAM_BOT_TOKEN из окружения. Без --recipient-id
обрабатывается общая очередь. Размер пакета — от 1 до 100 записей.
Управляющий процесс не запускается автоматически вместе с polling-ботом:
на этом этапе отправка выполняется отдельной командой.

Сообщения отправляются обычным текстом, без HTML-разметки. Таймаут одного
запроса — 10 секунд. Бот не пишет в публичные чаты: адресат берётся из
привязки User.telegram_id, созданной в личном чате.

## Ошибки и повторы

- Успех: status=sent, заполнен sent_at. Повторный запуск не выбирает sent.
- Временная ошибка: status=failed, retry_count увеличивается. Следующий
  запуск повторяет попытку; после трёх неудач автоматические попытки прекращаются.
- Нет доступа, удалённая запись, устаревшее событие или отказ Telegram:
  запись помечается failed с исчерпанными попытками и кодом причины.
- Ограничение скорости: пакет останавливается, команда печатает задержку.
  В payload сохраняется _delivery_not_before; до этого времени запись не
  отправляется. Повторять запуск следует после указанной задержки.

В Admin → Notifications видны статус, число ошибок и код причины.
Сырые сетевые исключения и URL с токеном не сохраняются в поле error.
Не переводите sent обратно в pending без проверки: это может повторить доставку.

## Ограничения доставки

Работники используют SELECT FOR UPDATE SKIP LOCKED, чтобы не отправлять
одну запись одновременно. Блокировка держится во время сетевого запроса;
это простая реализация для небольших пакетов, не очередь высокой нагрузки.

Гарантия доставки — at-least-once, не exactly-once. Если Telegram принял
сообщение, а процесс завершился до фиксации sent в PostgreSQL, повторная
попытка может доставить дубль. Уникальность очереди не устраняет эту границу
между двумя системами. Настройка постоянного фонового процесса и мониторинга
остаётся этапом развёртывания.
