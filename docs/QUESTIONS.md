# Вопросы родителей и ответы преподавателей

## Родителю

`/children` → ребёнок → **Вопросы преподавателю** → **Задать вопрос**.
Выберите преподавателя и отправьте текст до 500 символов. Текст сразу
сохраняется как вопрос. `/cancel` или кнопка «Отмена» прекращают ввод.
В истории можно открыть вопрос и отдельно прочитать ответ. Кнопка
«Обновить» перечитывает текущие данные; сначала показаны вопросы без ответа.
Фильтры «Без ответа», «С ответом» и «Все» доступны обеим ролям. В списке
видны дата по Ташкенту и начало вопроса: преподавателю показывается ребёнок,
родителю — преподаватель. Переключение фильтра начинает с первой страницы;
переходы между страницами сохраняют фильтр. Кнопка «К вопросам» из карточки
возвращает к общему списку. Старые кнопки общего списка остаются рабочими.

Доступны активные преподаватели текущих групповых и индивидуальных
зачислений ребёнка. Учитываются статус зачисления и его даты по Ташкенту.
Если список пуст, администратор должен проверить зачисление и преподавателя.

## Преподавателю

`/menu` → **Вопросы родителей**, либо `/questions`.
Откройте обращение и нажмите «Ответить», затем отправьте до 500 символов.
В MVP сохраняется один ответ; повторная отправка не заменяет его.
Вопрос и ответ отображаются отдельно, длинные записи из Admin — по страницам.
Отмена, переход к детям, группам, расписанию или главному меню прекращает
незавершённый ввод. Вложения не принимаются: бот предлагает написать текст.

## Доступ и история

- Родитель видит только собственные вопросы по ребёнку с актуальной связью
  ParentStudent. Другой родитель того же ребёнка не получает эту переписку.
- Учитель видит адресованные ему вопросы, только пока имеет активную роль
  Teacher и ведёт ребёнка по действующему зачислению. Активность родителя,
  его роль Parent, связь с ребёнком и активность ученика проверяются вновь.
- После смены преподавателя старое обращение не передаётся новому учителю.
  Родитель сохраняет свою историю, пока сохраняется доступ к ребёнку,
  и может создать новый вопрос текущему преподавателю.
- Проверки повторяются при сохранении. Два ответа одновременно дают одну
  запись; повторное использование формы вопроса не создаёт дубль.
- Черновики хранятся в памяти бота. После перезапуска незавершённый ввод
  нужно начать заново. Сохранённые вопросы и ответы остаются в PostgreSQL.

## Уведомления

Сервисы создают события `question_asked` для преподавателя и
`question_answered` для автора вопроса, если у адресата привязан Telegram.
В очередь попадает ссылка на раздел; текст переписки читается после
повторной проверки доступа. Создание записи и события атомарно.
Перед доставкой доступ проверяется ещё раз. Отправка требует работающего
обработчика очереди — см. [NOTIFICATIONS.md](NOTIFICATIONS.md).
Прямая запись через Django Admin уведомлений не создаёт.

Использованы существующие модели Question и Answer; миграций нет.
Это один вопрос и один ответ, без многостороннего чата и редактирования ответа.
