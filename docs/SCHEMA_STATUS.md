# Schema Status — актуальное состояние на 2026-10-05

Реализованы 18 моделей. Этот файл — краткий снимок состояния кода;
он не заменяет подробную архитектурную документацию.

## Apps и модели

- users: User (custom), Role, UserRole, InviteCode.
- education: Student, Subject, Group, Enrollment, Schedule, Lesson,
  Attendance, Grade, Question, Answer, ParentStudent.
- billing: BillingPeriod, Payment.
- notifications: Notification.

## Основные решения

- Enrollment задаёт либо Group, либо Subject + Teacher; сочетание
  контролируется CHECK-constraint. Enrollment.group использует PROTECT:
  SET_NULL нарушал бы constraint для группового обучения.
- Schedule задаёт либо Group, либо Enrollment; обе связи используют PROTECT.
- Lesson.teacher и Lesson.subject сохраняют исторический snapshot.
  Grade.given_by_teacher сохраняет автора оценки.
- BillingPeriod.amount_due — snapshot суммы начисления.
- Notification имеет уникальность по recipient + event_key.
- InviteCode обеспечивает одноразовую привязку Telegram к созданному User.
  У пользователя может быть не более одного active-кода.
  Поле code имеет unique=True; избыточный db_index=True удалён
  миграцией users.0004_alter_invitecode_code.

## Service layer и доступ

В education/services.py реализованы update_group, change_group_teacher,
mark_attendance, create_enrollment и add_grade: защита предмета группы
с учебной историей, обновление учителя planned-занятий, проверка допуска
и upsert посещаемости, проверка пересечений Enrollment и согласованности
Grade с Lesson.

В education/authorization.py реализованы проверки конкретных связей
учителя с обучением и родителя с учеником через ParentStudent.

## Telegram Bot — Phase 6.1 и первый шаг Phase 6.2

Реализованы запуск через python manage.py run_bot, polling для разработки,
auth middleware, /start и обработка invite-кода. Приложение bot включено
в INSTALLED_APPS. Активация invite-кода атомарна, блокирует повторное
использование и перезапись существующей Telegram-привязки.

Добавлено меню /groups: собственные активные группы преподавателя,
занятия, список учеников и четыре статуса посещаемости. Списки имеют
постраничную навигацию. Каждое действие проверяет активность аккаунта,
роль Teacher и связь преподавателя с группой и занятием. Посещаемость
сохраняется через education.services.mark_attendance; дата зачисления
проверяется по локальному времени Ташкента. Отменённые занятия недоступны.
Групповые чаты не обслуживаются; данные доступны в личном чате с ботом.

В карточку ученика добавлены оценки: кнопки 2/3/4/5 и ввод своего значения
до 16 символов (шкала не ограничена пятибалльной). Оценка создаётся через
add_grade с определением Enrollment на локальную дату занятия, сохранением
автора и времени. В карточке видны последние пять оценок за это занятие.
Старые кнопки после сохранения отклоняются, включая одновременные нажатия.
Новая оценка добавляется через заново открытое меню; прежняя не заменяется.
Ввод своей оценки отменяется кнопкой, /cancel, /groups или /start.

В журнале показаны прогресс посещаемости и число учеников с оценками
по всем страницам. «Следующий неотмеченный» выбирает актуального ученика
без отметки. «Итоги занятия» показывает сводку по статусам посещаемости.
Заполнение всех отметок не меняет автоматически статус Lesson.

Учителю доступен /schedule с периодами «Сегодня», «Завтра» и «7 дней»
по времени Ташкента. Он показывает назначенные групповые и индивидуальные
занятия, исключая отменённые. Из расписания открывается журнал занятия.
Индивидуальные посещаемость и оценки используют точный Enrollment из
Schedule; чужие, неактивные и недействующие на дату зачисления отклоняются.
Для демо на 2026-10-05 подготовлены группа в 18:00 и индивидуальное занятие
в 19:00. Новая команда seed_teacher_demo --teacher-id ID --individual
позволяет повторяемо готовить оба сценария.

По результатам ручной проверки бот отвечает в Telegram, /start работает,
неверный и истёкший коды отклоняются. 2026-10-04 пользователь подтвердил
успешную активацию приглашения и открытие /groups. В БД подтверждены
погашение кода, Telegram-привязка и роль Teacher. Сохранение посещаемости
через Telegram подтверждено: одна запись «Опоздал», корректный автор и время.
Пользователь также подтвердил сохранение оценки 5 и её отображение
в карточке ученика. Повторный /start после активации, изменение посещаемости
и новая сводка занятия ещё требуют живой проверки.

Для живой проверки в dev-БД добавлены отдельная группа [DEMO], два
вымышленных ученика и занятие на 2026-10-04 в 18:00 (Asia/Tashkent).
Команда seed_teacher_demo --teacher-id ID создаёт демо-данные повторяемо,
без дублей за тот же день и без перезаписи существующих отметок.
Она доступна только при DEBUG=True.

## Родительское меню — первый шаг Phase 7

/children показывает активных детей, связанных с пользователем через
ParentStudent. Каждое открытие карточки проверяет активность аккаунта,
роль Parent и актуальность связи. Разделы: оценки, история посещаемости
и ближайшие запланированные занятия. Списки разбиты на страницы по пять
записей; кнопка «Обновить» перечитывает данные.

История оценок и посещаемости доступна и после завершения Enrollment.
Ближайшие занятия учитывают активное зачисление на локальную дату занятия
для группового и индивидуального обучения; отменённые занятия исключены.
Родительские обработчики не изменяют учебные записи.

/start и /menu показывают кнопки по назначенным ролям: «Мои группы» и
«Моё расписание» для Teacher, «Мои дети» для Parent. Роль сама по себе
не даёт доступа к чужой группе или ребёнку. Живая проверка родительского
меню в Telegram ещё не выполнена.
